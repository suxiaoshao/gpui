# Gupi 统一设置开发计划

初稿：2026-09-15；子页面与实现方案调研补充：2026-09-16。归属：[#231](https://github.com/suxiaoshao/gpui/issues/231)，父 issue #217。

状态：应用侧八页、字段搜索接线、独立保存、快捷键及个人资源管理已实现。共享 Settings 搜索修复已完成本地接入验证，正式依赖仍为 0.6.0；在发布并接入修复版本前，不能将正式依赖的搜索行为标为完成。

2026-09-16 用户确认：搜索问题留待后续更新 gpui-kit 版本时解决。升级时确认版本实际包含修复并完成过滤/选择回归；该遗留项统一登记在[主 Issue 未完成项索引](../../../../../docs/dev/issue-217/follow-ups.md)，本轮不复制组件或增加临时绕过实现。

## 已确认方向

- 优先做设置的设计基础，再推进临时窗口，使后续功能能接入同一套设置。
- 设置作为一个整体，包含现有通用设置、快捷键、插件、Skill、提示词管理，不按每个栏目拆成独立 issue。
- 左侧侧边栏提供不同类型，右侧显示相应页面；采用通用、外观、Pi、快捷键、插件、Skill、提示词、关于八页。
- 搜索入口放在侧边栏，覆盖各页面的设置字段，采用分类筛选；不搜索具体插件名、Skill 名、提示词名称或这些管理内容的正文。
- 保存方式按具体内容判断：主题、语言等即时保存；列表添加、插件下载等明确操作完成后及时保存对应结果；需要显式保存的内容保留明确提交入口。
- 本次设置仅管理个人级 Pi 资源，不显示项目选择器，不依赖是否打开项目或会话，也不读取或修改项目级配置。后续如做项目级设置，从 session 中的独立对话框进入，本次不实现。
- 提示词页包含 Pi 命令模板和系统提示词；后续临时窗口直接使用命令模板，不另设计 Gupi 自定义 prompt。
- 包负责安装、更新和移除；包内扩展、Skill、模板按资源展示，不在各页重复实现安装器。自有 Skill 和模板可创建、编辑、删除，包内文件只读。
- Skill 停用使用 Pi 资源过滤规则，表示不加载；不通过修改 SKILL.md 的 disable-model-invocation 代替停用。
- 资源变更后由用户手动刷新需要更新的会话，不自动重连运行中的任务。
- Pi 路径显式保存，测试按钮只检查；键位确认后及时保存，冲突先反馈，不默认覆盖其他绑定。
- 参考已有 Jaco 和本地 Zed 的设置实现，优先复用现有组件。

## 源码核对结果

| 对象 | 本轮核对的实现 | 适用结论 |
| --- | --- | --- |
| Gupi | `features/settings.rs`、`features/settings/preferences.rs` | 常规设置采用八页分类；即时偏好与 Pi 路径分开提交，启动引导仍由 SettingsView 承接 |
| Jaco | `features/settings.rs`、`features/settings/layout.rs` | 左侧搜索与分类、右侧独立页面；SettingsPageSpec 登记页面级搜索文本，全局搜索主要筛选页面，没有通用的逐字段筛选 |
| Zed | 本地提交 `ba7da93e5c`，`crates/settings_ui/src/settings_ui.rs` | 根据页面、分组、字段标题及说明建立搜索信息；合并词前缀与模糊匹配，过滤具体设置项，选择匹配页面并滚动到匹配位置；搜索任务在后台执行 |
| gpui-kit / gpui-component | 当前依赖 0.6.0，`setting/settings.rs`、`setting/item.rs`、`setting/page.rs` | Settings 已包含可调整宽度的侧边栏、搜索、分类页面和分组导航；SettingItem 按标题、说明和 keywords 做不区分大小写的子串匹配，支持自定义内容渲染 |

组件的分类页和分组标题不会自动成为每个字段的匹配词；若需要按分类名称找到相关字段，应将其纳入字段关键词。自定义 SettingItem 的搜索依赖 keywords，不能假定组件会扫描自定义控件中的可见文字。

## 已确认的资源管理范围

### 插件与包

- 展示已安装的个人 Pi 包与本地扩展，区分包和扩展；显示可取得的来源、版本、路径，以及包包含的扩展、Skill、模板、主题。
- 支持输入 npm、Git 或本地路径安装 Pi 包，支持单包更新和移除；复用 Pi 包管理能力。
- 扩展按 Pi 资源配置语义启停，不以卸载整个包代替停用某个扩展。
- 本次不做插件市场、推荐榜单、自动更新、自建 UI 插件体系或各插件专用配置页。

### Skill

- 从个人配置及资源路径发现列表，包含禁用资源与包内 Skill，不依赖当前 session 的已加载列表。
- 页面内部可按名称和说明搜索，查看来源、文件位置与正文；此搜索独立于侧栏的设置字段搜索。
- 启停沿用 Pi 加载规则；disable-model-invocation 仅限制模型自动调用，与不加载不同，本次不将它作为停用开关。
- 添加本地文件或目录时登记资源路径，不自动复制或接管外部文件。支持创建、编辑、删除自有 Skill；正文使用显式保存，不引入额外草稿持久化系统。
- 包内 Skill 只读并提供查看所属包入口；更新、移除由所属包管理，不另建 Skill 更新机制。
- 本次不做社区 Skill 市场，也不直接编辑或删除包内 Skill 文件。

### 提示词

- 命令模板支持查看、创建、编辑、删除；包内模板只读，展示所属包。
- 个人 SYSTEM.md 和 APPEND_SYSTEM.md 分别编辑，明确替换系统提示词与追加内容的区别。
- 本次不做模板市场；临时窗口复用命令模板，不增加另一套提示词模型。

以上资源变更成功后保存对应配置或文件；已有会话由用户手动刷新，不自动重连，也不把安装成功显示成会话已经加载。

## 已确认的搜索交互

保留分类结构，按匹配结果过滤字段：

1. 侧边栏搜索覆盖所有设置页面，不限当前页。
2. 左侧只显示有匹配项的分类。
3. 右侧显示所选分类中匹配的设置行，保留相应分组标题，可直接修改原控件。
4. 当前分类仍有匹配时保持；没有匹配时转到有结果的分类。
5. 清空搜索后恢复完整内容；无结果时提供明确的空结果提示。

搜索仅覆盖设置字段，匹配信息包括字段名称、说明、分类名称和别名；不索引具体插件名、Skill 名、提示词名称及正文。例如“深色”“暗色”“dark”可以指向颜色模式。先复用组件已有匹配，不因参考 Zed 就引入同等规模的独立索引或后台搜索系统。

右侧不建立跨分类汇总结果页。

## 组件接入

复用现有组件：

```text
Settings
  SettingPage
    SettingGroup
      SettingItem
        SettingField / 自定义控件
```

每个字段同时提供展示内容和搜索关键词。特殊控件使用 SettingItem 的自定义渲染入口；避免把整页做成唯一一个搜索项，导致只能命中页面、无法筛选到字段。

复用现有 Gupi 配置与表单绑定，按下方原则划分提交范围，不由页面改版增加文件监听或改变配置来源。共享组件需要补齐的能力见下方实施设计；自定义列表使用公开渲染入口。

## 已确认的保存原则

保存方式按具体内容与操作判断，不要求所有设置统一自动保存或统一点击保存。

| 内容或操作 | 已确认方向 |
| --- | --- |
| 主题、语言等适合即时变更的设置 | 修改后即时保存，无需再点击统一保存按钮 |
| 列表页面添加一项 | 完成添加操作后及时保存，无需再提交整张设置页 |
| 插件页面点击下载 | 直接执行该操作并在完成后保存对应结果，无需再点击设置页保存 |
| 其他需要明确提交的内容 | 使用显式保存；具体字段与提交范围随页面设计判断 |

“及时保存”针对对应的设置变更或已执行操作，不表示将添加表单中尚未提交的文字自动保存，也不表示下载开始就标记为成功。具体提交范围以上方页面表为准。

资源操作的来源与范围按上方已确认内容实施，不因采用其他客户端作为参考扩大范围。

## 实施设计

### 1. 页面与组件

继续使用现有主窗口中的设置入口。Jaco 的独立设置窗口可作参考，但本次左右布局不要求改变窗口生命周期；启动引导保持自己的步骤式流程，和常规设置复用字段控件即可。

优先使用组件的 Settings / SettingPage / SettingGroup / SettingItem，普通页面使用标准字段，复杂管理页面通过自定义内容接入。自定义管理列表只登记固定设置能力的关键词，不将插件、Skill、模板实例名称送入侧栏搜索；全局搜索不代替管理页自身的列表操作。

关于页也是普通 SettingPage：版本等只读行使用现有组件，自定义展示通过 SettingField/SettingItem 的渲染入口接入；关闭不适用的页面重置入口。

依赖缺口已定位：Settings 0.6.0 过滤时丢失页面/分组的原始索引，渲染时将保存的选中索引与过滤后数组索引比较；SettingsState 私有，公开的默认选择不能修正搜索过程中的选择。因此搜索可能切换到另一个分类，或在选中索引越界时显示空白。已在独立组件工作区修复，并通过两项定向回归；正式 0.6.0 仍包含此问题。

先在共享组件中保留过滤前的页面/分组身份，并让侧栏选择、右侧页面和滚动目标使用同一身份；当前页仍匹配时保留，否则选择首个匹配页，无结果时显示空提示。清空搜索恢复完整内容，保留当前有效分类，不增加“返回搜索前页面”的第二份选择状态。空提示使用组件本地化入口。以最小组件改动交付，再接入包含修复的依赖版本；不修改 Cargo registry 文件，不在 Gupi 复制 Settings，也不访问其私有状态。是否需要新增公开 API 由最小修复决定。

外观的浅色/深色选择应分别成为可搜索项，不把整个主题页作为一个不可拆分的搜索单元。先沿用组件留白和原有主题控件，不另造一套通用设置行框架。

### 2. 配置保存与编辑边界

AppConfig 保留 pi_command、theme、light_theme、dark_theme、language，并增加可选的 keybindings 覆盖表。submit_draft 的整份表单提交用于启动引导；常规设置新增独立的 PiSettings 表单与 submit_pi，主题/语言使用 set_preference 的单项提交。write_config 继续读取最新文件、按本次变更合并字段并原子写入，避免换主题时顺带保存未确认的 Pi 路径。

确定的实现方式：

- 保留一个配置持久化负责人和现有文件存储，不为各页面创建互不协调的文件写入逻辑。
- 已保存 AppConfig 仍是持久配置的唯一来源。常规设置的主题/语言控件发出单项变更，写入成功后立即应用；失败维持已保存值并显示错误。启动引导继续通过自身表单预览，不另建一份全局设置草稿。
- 常规设置中 Pi 路径使用独立的 typed Form，保存只提交路径；即时设置不能触发这个表单的 prepare/rebase。启动引导保留一次确认整份配置的流程，两处复用字段控件，不同步两份编辑草稿。
- 需要多个字段共同确认的操作以同一份表单为编辑单元；不能通过保存另一页清空或顺带提交这份草稿。
- 配置落盘继续复用现有原子写入与错误状态；异步保存结果不得覆盖较新的编辑。
- 页面切换只改变展示，不作为隐式保存入口。自动保存失败要有可见反馈，不把写入失败显示成已保存。
- 即时设置写入失败后展示错误并恢复已保存值；Pi 路径或正文保存失败时继续保留当前输入供修改，再次点击保存即可，不增加失败草稿存储。
- 沿用单一配置写入 Operation，保存期间禁用会产生另一次配置提交的控件，完成后恢复；不让现有 busy 检查静默吞掉用户修改，不为此增加保存队列。

gpui-form 的 rebase 作用于整份编辑模型，当前没有公开的单字段基线提交接口，因此以独立编辑单元隔离显式保存。提交时记录 FormVersion，成功后仅 rebase 对应且版本仍匹配的表单。文件读取时保留最新文件中非本次修改字段，继续使用现有原子落盘方式，不新增配置冲突审阅流程、额外数据库或文件监听。

### 3. 快捷键接入

当前默认绑定位于 app.rs 和 features/home/actions.rs，业务仍由同一组 action/context 处理。设置页可以围绕这些动作展示与修改绑定，菜单和 tooltip 继续查询实际 keymap。

Jaco 有 HotkeyInput 按键录入控件，但其快捷键页面主要管理“全局热键 + prompt + 模型”的动作，不能整体移植成 Gupi 应用内快捷键页。可评估复用按键录入本身，避免复制其数据库、模型与临时窗口逻辑。

键位存储放入现有 Gupi config.toml 的可选 keybindings 字段，仅存用户覆盖；缺省仍使用默认绑定，恢复默认删除对应覆盖。用稳定的应用命令 ID 映射现有 action 及其上下文，同一命令在多个上下文的绑定一起更新。不要序列化任意 GPUI action：当前 Run(Kind) 使用 no_json，而且多个 Kind 共用 action 类型。文本编辑器和列表的基础按键仍归组件，不加入应用命令配置范围。

GPUI 的 bind_keys 只追加，Unbind 按 action 名称匹配，不能单独区分 Run 中不同的 Kind。动态更新采用现有公开接口重建绑定集合：读取当时完整 keymap，识别并替换 Gupi 自己登记的应用命令绑定，在同一次同步更新中 clear 后恢复集合。完整保留其余绑定、元数据及相对优先顺序，替换尽量保持原登记位置；不能只重新注册 Gupi，也不能使用启动时缓存的一份组件绑定。应用设置成功后立即生效，菜单与 tooltip 查询更新后的真实 keymap。

录入通过 GPUI 的可失败解析接口校验，不能用会 panic 的构造器处理用户文字。上下文由应用命令定义，不开放任意 context 编辑。冲突检查依据实际焦点上下文和绑定优先级，比较同一可生效范围的按键及前缀；不同上下文互斥的绑定、同一逻辑命令的多个入口不能误报。提示与哪个操作冲突，不自动覆盖；现有默认绑定的有意重叠不作为本轮全局清理对象。确认后仅持久化该覆盖，成功后更新运行时；失败继续显示原绑定与错误。

### 4. 个人级 Pi 资源管理的数据来源

本轮核对本地 Pi `71dca871b` 的源码与文档，未更新上游、未执行安装或修改用户配置。

- Pi 包可以同时包含 extensions、skills、prompts、themes。包安装、包移除与某个 extension 启停是不同粒度，不能把每个 slash 命令显示成一个已安装插件。
- CLI 使用 `pi install <source> --no-approve`、`pi remove <source> --no-approve`、`pi update --extension <source> --no-approve`，不使用 -l。--no-approve 在当前源码中将 projectTrusted 明确设为 false，项目设置不会加载，更新也只遍历个人包；仅省略 -l 不足以隔离项目。裸 pi update 更新 Pi 自身，不用于包更新。
- pi config 是终端交互入口，没有对应的通用设置写入 RPC。本次原生管理页只处理个人级资源过滤与配置，不合并项目覆盖；依据 Pi 已有配置语义接入，不能靠发送同名 RPC 实现。
- RPC get_commands 返回当前会话注册的扩展命令、已加载的模板与 Skill，不提供全部已安装包、禁用资源或完整正文。管理目录需要从 Pi 配置、资源路径和适用的 CLI 能力取得，不能依赖打开某个会话后才有数据。
- 包安装使用 Pi CLI，避免另写 npm/git 安装器。pi list 是终端展示，不解析其彩色文本构建数据模型；目录由个人 settings.json、包 manifest 与资源文件读取构建，具体契约见下文。

所有包操作调用已保存并探测通过的 Pi 命令，使用独立 argv，不拼 shell 命令。工作目录固定为个人 agent 目录，本地来源先解析成绝对路径，不借用当前 session 的 cwd。个人目录沿用 PI_CODING_AGENT_DIR / 默认 ~/.pi/agent 的规则。当前 CLI 参数依据上述源码版本，接入时对实际配置的 Pi 核对支持情况；不支持就反馈该命令错误，不退化成带项目作用域的执行。

目录读取与写入契约：

| 对象 | 读取 | 修改 |
| --- | --- | --- |
| 包 | 个人 settings.json 的 packages，保留字符串/对象来源；从安装路径和 package.json 读取版本、Pi manifest 与资源组成 | 安装、更新、移除交给 CLI，结束后重新读取个人目录 |
| 本地扩展、Skill、模板 | 个人自动发现目录与配置路径；Skill 同时包含 ~/.agents/skills，保留它自己的路径基准；不遍历项目祖先目录 | 新增外部路径只登记个人对应数组；启停使用对应资源过滤规则 |
| 包内资源 | manifest 或 Pi 约定目录，记录所属包、资源类型、路径、启用状态；先发现再过滤，禁用项仍可见 | 更新对应 packages 对象的资源过滤字段；正文只读 |
| 自有 Skill / 模板 | 从资源文件读取元数据与正文，编辑时再读目标文件 | 独立编辑表单，显式保存目标文件；删除仅针对所选自有资源，不删除共享资源根目录或包目录 |
| 系统提示词 | 个人 SYSTEM.md、APPEND_SYSTEM.md，未创建时可编辑空内容 | 明确保存后创建或更新对应文件，不创建额外 prompt 存储 |

包路径解析遵循 Pi 的 getInstalledPath：受管理 npm 目录优先，兼容已有全局 npm/bun/pnpm 安装位置；Git 使用个人 git 安装根及来源解析后的 host/path；本地来源相对个人配置目录解析。不要将所有 npm 包都假定在全局 node_modules，也不要靠目录名猜 Git 来源。只做元数据发现，不为列出扩展而 import/执行其入口；不调用会自动安装缺失包的 resolve 流程。缺失文件或无法解析的来源展示对应问题，其他可读资源继续可用，不将错误当成“未安装”并自动安装。

资源过滤遵循 Pi package-manager.ts 与 config-selector.ts：顶层规则和包内规则使用各自 baseDir；普通模式/! 排除与 +精确路径/-精确路径语义不同。包过滤字段省略表示默认发现，空数组表示该类全部停用，autoload:false 还有独立的增量语义，不能将三者归一化。修改单项时保留其他规则和字段，按目标路径移除旧的精确覆盖再写入新覆盖；已有空数组/通配规则时验证其他资源状态不被意外改变。目录保持完整可发现条目，加载规则只计算状态；不修改 disable-model-invocation。

写个人 settings.json 前读取最新对象，只更新此次目标路径数组或包内过滤字段，保留其他键及未知字段，原子写入。Gupi 内包 CLI 与直接配置写入串行执行，CLI 退出后重新读取，避免自己覆盖自己的更新；不持有整份 Pi 设置的长期编辑副本。外部同时修改不新增冲突检测流程，本次也不增加监听。

管理列表展示个人资源的名称、说明、来源和配置/操作状态，不添加重复的作用域列，也不把某个当前 session 的加载状态当作全局状态。安装成功与现有会话已经加载成功是两件事，资源变更后由用户手动刷新需要更新的会话，沿用手动重载的交互，不自动重连正在运行的任务。具体提示入口在页面设计中确定。

### 7. 所有权与异步操作

沿用应用既有分层，不新增通用设置框架：

| 负责人 | 职责 |
| --- | --- |
| features/settings 及其页面模块 | 页面选择、字段关键词、控件与当前编辑表单；复用组件样式 |
| state/config 的现有控制器 | AppConfig 存取、即时变更与显式提交的串行化；启动引导仍复用同一配置存储 |
| 应用命令/键位模块 | 默认绑定与用户覆盖的唯一映射、运行时应用、冲突说明；设置页不复制动作处理逻辑 |
| 个人 Pi 资源控制器 | 设置页共享的目录快照、读取与资源变更 Operation；插件、Skill、提示词三页复用同一来源关系 |
| foundation 的 Pi 资源文件/CLI 适配 | 路径与规则解析、原子写入、进程调用；不耦合页面，不扩展 pi-rpc 的协议类型 |
| StartupView / PiProbeController | 保持 applied_pi 与 draft_pi 的既有区别；关于页只投影 applied_pi |

资源控制器由设置功能持有，切换子页面不重建任务；不创建每页独立扫描器和独立配置写入者。读取使用 gpui-operation 的 refresh，显式变更沿用 repair 模式；使用框架状态表示运行中/结果/失败，不另外堆叠 loading、saving、pending 等同义标志。概念流程为：

```text
目录：未读取 → 读取中 → 可用 / 读取失败 → 用户重新读取
变更：可提交 → 执行中 → 成功 / 失败
                          成功 → 重新读取目录
                          失败 → 显示错误，允许重新操作
```

读取失败和变更失败分别归属对应操作，不清空已经可用的目录。变更完成后的读取失败应说明“操作成功，列表读取失败”，不能诱导用户再次安装。包 CLI 失败也重新读取实际目录，因为退出码不能证明文件完全未改动；不额外实现安装回滚或后台自动重试。

文件与进程工作放后台 task，使用现有 gpui-tokio 接入文件/进程 IO，CPU 解析按需放后台执行；设置字段搜索规模小，直接使用组件匹配即可。运行中变体拥有任务，设置控制器接收结果更新 UI，子页面渲染不启动 IO。目录扫描只依赖个人文件，不依赖 Pi 命令，不因命令变化额外重扫。包操作提交时要求 saved Pi 的探测结果仍匹配，捕获该次命令和目录；包变更期间禁用 Pi 路径保存及其他资源写入。持久控制器使关闭设置页面不把正在进行的包操作丢弃；应用退出遵循现有进程/task 生命周期，实施时核实新启动 CLI 子进程的 drop 行为，不把丢弃 Rust task 等同于包文件回滚。

### 页面整理

- 所有设置页面统一使用 Settings 自带的 `Normal` 无边框分组样式，保留分组标题与独立设置项。
- 通用页使用标准设置行，语言只保留字段标签，不再重复分组标题；配置文件使用独立 `SettingItem`，标签在左，右侧字段内依次显示只读路径 Input、重读图标和打开文件图标，打开操作交给系统默认应用。窄窗沿用 Settings 的纵向布局。
- 外观页移除内容设置项内部的 `container_query`。该用法原本让两个主题区高度计算为 0；主题卡片按实际内容宽度计算列数，使用等宽 Grid，末行不单独拉伸；在布局阶段测量实际卡片高度并计算行数，同一帧按分配宽度绘制网格，不缓存列数或等待补刷，由测量结果撑开父级高度，沿用 Settings 的滚动。浅色与深色主题为独立分组，说明各自的生效模式。
- Pi 路径输入从对应表单显式初始化，避免将绑定后续同步误当作首次回填。Pi 路径的检查与保存就近排列，显示未保存状态，没有修改时禁用保存。检查仍不提交路径。
