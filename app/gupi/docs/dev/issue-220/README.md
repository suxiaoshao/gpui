## 本轮边界

已确定会话发现范围、新建/恢复流程、Pi 原生能力、草稿与会话选择持久化，以及下文的两级 Sidebar、项目/session 右键菜单和整体布局。整体参考 Codex 的阅读与导航结构，内容只承接本阶段 Pi 原生能力。

设置页重设计及手动会话目录管理延后，不属于本轮设计或实现的完成条件。本轮保留现有设置入口，会话发现使用默认目录和已知 Pi 配置目录。

新建页面、共用输入框、发送/换行快捷键、统计圆环、Command 弹出搜索、扩展交互临时替换主输入区，以及下文消息过程折叠规则均已确定。后台运行、等待输入和失败先只通过侧边栏状态提示，不追加应用内或系统通知，不自动切换会话。

历史浏览采用从旧到新的分支树，标题行使用图标 Toggle Group 切换简略列表、详细列表和画布；两个列表不自动收起过程记录，画布支持连续段折叠。其他分支预览暂停普通发送并保留草稿，提示条提供返回当前分支，支持位置的用户消息菜单提供另开会话。

字体、间距、输入框最大高度、圆环具体位置、搜索结果行、常规加载与错误反馈等细节，按已有参考、主题和组件惯例在实现中处理，不要求逐项先行确认。

页面设计不扩大现有功能或 Pi 协议范围。功能与数据层沿用开发计划。

## 信息结构

项目以会话 header 的 cwd 为依据，项目下有多个会话文件；每个会话文件内部有一棵通过 entry.id / parentId 连接的树。历史面板使用 entries 的父子关系展示分支树。

```text
项目（cwd）
  会话（Pi JSONL 文件）
    entries（分支关系、消息、压缩、标签等）
      当前分支对话 / 分支树
```

同名目录显示必要父路径。不同 worktree 的 cwd 分开归组，暂不通过 Git 根目录自动合并，避免把不同运行目录中的会话混为同一项目。

## 会话目录

使用 `gpui_kit::component` 的 Sidebar 组织 `cwd（项目）→ session` 两级导航。项目组内按最近消息活动倒序，项目本身按组内最近活动排序；排序相同时用稳定标识作次级排序。最近活动通过排序体现，首版不额外提供常驻的平铺视图切换。

日常创建流程为“新建会话 → 选择工作目录 → 启动 Pi”，按 cwd 自动形成项目分组，无需另设项目注册步骤。已有项目中新建可沿用该目录。工作目录选择属于本轮新建流程；手动会话存储目录管理随设置页延后。

会话标题采用最新 session_info 名称，没有有效名称时使用第一条用户消息摘要，再回退到未命名会话。最近活动采用所有分支 user/assistant 消息的最大时间，不能直接把文件 mtime 当作聊天时间；工具结果、改名和标签不改变此时间。时间只用于排序，不占会话行；fork 来源入口放到会话详情或历史视图。

本轮会话发现覆盖 Pi 默认目录和已知配置目录。默认根按项目子目录扫描，自定义 sessionDir 直接扫描 JSONL，遵守 Pi agent/session 目录覆盖配置并显示实际路径。已知配置来自全局、当前项目及已发现项目；未知项目的自定义存储目录本轮不主动发现，不扫描整个文件系统。重叠目录去重，保存真实文件路径，恢复时重新确认文件身份，不仅依赖显示标题或 session id。

后台扫描维护内存中的元数据列表，不增加专门的索引数据库或文件监听服务。每次启动先展示空白新对话，忽略旧状态文件中的 selected；项目默认收起，仅由用户展开。旧的非空草稿异步恢复，不抢占当前页面或输入，也不自动连接 Pi。空白新对话仅为内存状态，不列入侧边栏和草稿文件。启动、显式刷新和应用自身会话操作后更新；搜索覆盖名称、首条用户消息和项目路径。损坏或不可读文件单独提示；会话目录加载完成且没有会话时，主区域直接展示新建会话页面，可选择工作目录并开始对话，与顶部新建入口共用页面。搜索无结果不视为没有会话。首次加载用项目区域的 Spinner 和“正在加载会话…”替代列表，新对话仍可输入；后续刷新保留现有列表，在列表上方显示“正在刷新会话…”，完成后不改变当前页面及项目展开状态。

搜索入口打开弹出搜索框，复用 `gpui_kit::component::command` 的 Command / CommandState 并组合现有 Dialog。搜索范围仍为全部已发现会话，不受侧边栏最近 5 条限制。沿用组件的查询、选中和键盘导航；确认结果后打开对应会话，关闭弹层时恢复合理焦点。分组和结果行的常规细节在实现时按目录数据确定，不另做一套搜索组件。

### 已确定的侧边栏呈现

| 位置 | 常驻显示 | 补充行为 |
| --- | --- | --- |
| 顶部 | 新建会话、搜索入口 | 新建可选择其他工作目录；搜索覆盖所有已发现会话 |
| 项目行 | 展开箭头、目录名 | 同名补充父路径；完整路径悬停查看；悬停出现 `＋`，在该 cwd 新建 |
| 会话行 | 单行标题、选中高亮 | 标题过长截断，悬停查看完整标题；生成中、等待输入或失败时显示小标记 |
| 项目组末尾 | 需要时显示“查看更多” | 默认只显示最近 5 个会话，按需展开更多；搜索不受这 5 个限制 |
| 底部 | 设置、刷新会话目录 | 两个独立按钮；设置页重设计与手动目录管理延后 |

顶部的新建会话、搜索会话和底部的设置、刷新会话目录各自独占一行，分别响应悬停、焦点和点击。行布局沿用 Jaco 的统一高度、侧边栏主题色、标题截断与固定右侧操作区；项目整行折叠，展开和收起分别使用打开、关闭的文件夹图标；子会话采用紧凑间距、缩进和竖线。“查看更多 / 收起”位于会话列表之后，使用独立的弱化文字按钮，不套用会话行样式，竖线也不延伸到该按钮。 本次行布局修正已通过 Gupi 构建与 Clippy，并在临时数据窗口中检查四个独立入口、窄宽度长标题省略、整行折叠及新增按钮不触发折叠。文件夹开关图标和独立文字按钮的展开、收起也已在临时数据窗口中确认。

不常驻显示时间、消息数、会话 ID、文件路径或来源关系。普通空闲会话不增加状态标记；折叠项目有需要关注的子会话时，可在项目行汇总同一套必要状态，具体图形随视觉设计确定。

### 侧边栏状态

会话行保留单行标题、选中高亮和至多一个必要状态标记；图标的 tooltip/可访问名称说明状态。状态从该会话的实际加载、运行与待处理请求推导，不从“当前是否选中”或进程存在与否推测。

| 状态 | 触发条件 | 呈现 |
| --- | --- | --- |
| 空闲 | 普通历史、仅有草稿、正常完成、已主动停止或结束运行 | 不显示状态图标 |
| 加载中 | 正在创建或恢复会话、建立连接及获取初始历史 | 小型加载标记，tooltip 说明正在打开 |
| 运行中 | 正在生成、调用工具、自动压缩/重试或等待停止收尾 | 小型运行标记，tooltip 可说明具体活动；收到实际收尾结果后才退出此状态 |
| 等待输入 | 存在仍有效的 select/confirm/input/editor 请求 | 醒目的等待输入标记；点击会话后在其输入区处理 |
| 失败 | 创建/恢复失败、运行最终失败或连接异常退出等需要处理的错误 | 错误标记；点击会话查看错误及可用操作 |

存在有效交互请求时优先显示等待输入，其次为需要处理的失败、运行中、加载中；连接失败已使请求失效时清理等待状态。折叠项目按同一优先级汇总子会话。工具报错后 Pi 仍在继续处理时维持运行中，不把每次工具错误变为会话失败；后续成功恢复或重试消除对应失败。完成、停止、未落盘草稿、排队消息不额外增加永久徽标，选中高亮与这些状态独立。

后台会话不额外弹通知、不抢焦点；用户通过侧边栏切回来源会话。扩展显式调用 notify 的已有接口呈现仍按请求处理，这与 Gupi 自行追加后台提醒分开。

当前选中或刚创建的会话需要可见：展开所属项目并使其进入可见范围，不因“最近 5 个”隐藏当前项，也不改写 Pi 活动时间。会话展开只影响目录呈现，不同时启动这些会话的 Pi 进程。

```text
新建会话                   搜索

▾ gpui
    会话标题一
    会话标题二              ◌
    会话标题三

▾ pixiv-novel
    会话标题一
    会话标题二
    查看更多…

▸ pi
▸ gpui-component

设置
```

### 已确定的右键菜单

优先使用现有 Sidebar/context_menu 与原生菜单能力。右键只打开目标行的菜单，不隐式切换当前会话或启动 Pi；选择具体动作后再按目标执行。菜单始终绑定被点击的项目/会话，不按当前选中项猜测。

项目菜单保留三项：

| 操作 | 行为与依据 |
| --- | --- |
| 新建会话 | 以项目 cwd 创建会话，与项目行 `＋` 共用动作 |
| 在 Finder 中显示 | 定位项目工作目录；跨平台使用对应文件管理器文案 |
| 复制项目路径 | 复制完整 cwd，不启动 Pi |

会话菜单保留以下操作，按实际状态提供：

| 操作 | 行为与依据 |
| --- | --- |
| 重命名… | 原生 set_session_name；保存成功后刷新标题。不直接改 JSONL。会话未运行时先按正常恢复路径连接 Pi；纯未启动草稿不提供此操作 |
| 复制会话文件路径 | 复制真实路径，便于 CLI 恢复和定位；尚未落盘时不可用 |
| 在 Finder 中显示 | 定位会话文件；尚未落盘时不可用 |
| 停止生成 | 仅 Gupi 管理的会话正在生成时提供，复用 abort；停止后仍可继续对话 |
| 结束运行 | Gupi 管理的实例已空闲时提供，复用 PiState.close；释放进程，保留目录项、文件和输入草稿，再次打开可恢复 |

正常历史会话只有前三项；运行控制按生成中/空闲状态出现。“结束运行”不代表删除会话。菜单按上表顺序分为会话动作、路径操作和条件性的运行控制，以分隔线区分；不可用操作给出简短原因。

项目名由 cwd 得出，首版不增加项目别名或项目移除规则；归档、置顶等也需要额外应用状态，不纳入这组基础菜单。Pi 原生 RPC 没有删除会话命令，删除文件不是本轮菜单默认动作。从历史位置 fork 放在正文/历史节点操作中，避免对整个会话右键时无法表达分叉位置；clone、导出等原生能力可按后续实际需求讨论，不默认加入。

依据：Pi 0.85.1 的 rpc-mode.ts 已确认 set_session_name、abort、fork、clone；Gupi 已有 PiState.close 和 reveal_path 使用，剪贴板与 context_menu 在现有应用中有可复用的 GPUI 接入方式。菜单实现与必要验证归入开发计划现有四个提交。

## 已确定的整体布局

参考 Codex 的空间组织：默认“左侧导航＋主对话”，右侧历史按需展开。主要留白服务于对话阅读，采用低对比度分隔和简洁工具栏，不为每条助手回答增加外层卡片。

| 区域 | 默认内容 | 行为 |
| --- | --- | --- |
| 左侧 | 项目与会话列表、搜索、新建 | 两级 Sidebar，可折叠；与正文之间可拖动调宽 |
| 中间顶部 | 项目、会话标题；右侧历史开关图标 | 工具栏保持简短；历史按钮用 tooltip 说明用途 |
| 中间正文 | 当前分支对话，由旧到新 | 限制最大阅读宽度并居中；用户消息使用靠右的轻背景气泡，助手回答直接排版；工具过程显示简短记录，按需查看详情 |
| 中间底部 | 文本输入框；底行模型、思考强度与发送/停止 | 输入框与正文宽度对齐，固定在主对话区底部；生成时保留停止按钮，键盘仍可提交 steer/follow-up；输入草稿按会话保留 |
| 右侧历史面板 | “会话历史”分支树 | 默认关闭；展开后与正文定位联动，与正文之间可拖动调宽 |

正文与输入区保持连续的阅读列，宽窗口增加两侧留白，不无限拉长文字行。具体默认宽度可结合真实 GPUI 字体效果微调。窄窗口中右侧历史以覆盖方式展开，避免把正文和输入区挤得过窄；收起面板不会结束 Pi 会话。

工具栏和面板开关使用图标按钮，不在右上角显示“历史”文字。悬停/键盘聚焦提供 tooltip，例如“会话历史”“收起会话历史”；同时提供可访问名称。搜索、侧边栏开关、复制、发送/停止等图标动作采用同一方式。导航项、菜单项和模型选中值保留必要文本。

### 模型与思考程度选择

- 使用合并的模型与思考程度 Popover，模型页复用可搜索 List，思考页使用离散 Slider 和本地化档位标签。模型按供应商分组，可搜索名称、ID 和供应商；候选选中值使用稳定的供应商/模型 ID，搜索与刷新不会按行号改变选择。关闭或取消菜单不写入 Pi。
- Pi 的 `get_available_models` 返回完整可用列表，应用在快照加载阶段读取 Pi agent 目录的 `settings.json`，应用 `enabledModels`。已持久信任的项目（含父目录信任，或全局 `defaultProjectTrust = "always"`）使用 cwd 下 `.pi/settings.json` 的范围覆盖全局；保留 `PI_CODING_AGENT_DIR` 路径规则。支持精确引用、模型名称/ID 的部分匹配、`*` / `?` / `[]` 通配符与思考程度后缀。未设置或空数组表示不限制；非空范围没有匹配时保持空列表，不回退展示被排除模型。配置读取失败只影响模型候选并显示错误，不阻断会话历史。
- 思考档位仍以 Pi 的 `get_available_thinking_levels` 为准，切换模型后刷新实际选中模型、档位和支持列表。运行或有会话操作时禁止更改；提交前再次校验候选仍可用。范围只控制候选，不改写已经运行的模型。
- RPC 未提供有效范围及运行时信任状态；本地配置投影不覆盖扩展动态修改、仅本次信任或 minimatch 的额外扩展语法。此处没有增加 Pi RPC 命令或注入扩展。

模型范围沿用既有 3 项关键回归。合并选择器另覆盖搜索刷新与取消、拖动预览/松开提交、过期档位与关闭失效，以及实际渲染滑杆的鼠标拖动提交。原生检查使用隔离模拟 Pi，不调用模型。

2026-09-11 验证：Gupi 全部 52 项测试、构建和 Clippy 通过。macOS 原生窗口确认合并入口、同一弹层的模型搜索/键盘确认、切换模型后六档变三档、无思考能力说明、滑杆点击及设置失败后恢复原档位并成功重试；模拟 RPC 记录与选择一致。1180px 窗口中用量与选择器同排，800px 窗口、320px 侧栏下用量换到上一行，模型名称、档位、发送按钮和弹层均完整可见。跨档拖动由实际渲染控件的 GPUI 鼠标事件回归验证；Computer Use 的整段拖动未可靠触发原生拖动，本轮不据此宣称真实设备拖动已验收。测试进程和临时会话已清理。

### 侧边栏宽度与 state.toml

- 左侧项目 Sidebar 和右侧历史面板的宽度都可通过分隔边拖动调整，分别记忆，不按项目重复保存。
- 分栏使用独立像素宽度和中间弹性正文，拖拽手柄复用 `gpui_kit::base::resize_handle`。不再使用按容器比例分配的 `h_resizable / resizable_panel`，也不通过嵌套分组绕开联动。左栏 160–480px，右栏 240–520px；普通布局给正文保留 360px，拖动到可用空间上限即停止，不借用另一栏的宽度。窄窗口的右侧覆盖层同样可拖动。
- 宽度存入 Gupi 现有 `state.toml` 布局状态，与主窗口位置和尺寸共存；不放进 config.toml 或 Pi 会话文件。
- 拖动时即时更新布局，拖动结束后保存；重新打开应用恢复上次宽度。面板收起或重新展开保留其宽度。
- 按当前窗口可用空间限制实际显示宽度，保证主对话可用。临时变窄或覆盖显示不覆盖用户原先保存的宽度；恢复空间后继续使用该宽度。
- 旧 state.toml 缺少新增宽度字段时使用默认值；局部无效宽度回退默认，不连带丢弃有效窗口状态。保存窗口位置时同时保留已有面板宽度。

### 发送与换行

| 快捷键 | 空闲时 | 生成期间 |
| --- | --- | --- |
| Enter | 发送普通 prompt | 提交 steer，修正本次运行后续执行的提示 |
| Option/Alt+Enter | 与普通发送一致 | 提交 follow-up，等待当前 agent 运行结束后处理 |
| Shift+Enter、Super+Enter（macOS 为 Cmd+Enter） | 换行 | 换行 |

生成期间输入框保持可编辑。steer 的投递时机、follow-up 的等待及队列消费顺序交给 Pi，不自行抢断模型请求或再建执行队列；输入法正在选词时 Enter 先完成组词。已接受或排队与实际开始执行分别反馈，发送失败保留可恢复输入。

主输入统一使用原生 `prompt`，根据快捷键传 `streamingBehavior: "steer"` 或 `"followUp"`，遵循 Pi 的扩展命令、输入处理及模板展开；空闲时按普通 prompt 执行。`followUp` 是该字段的实际值，与独立命令名 `follow_up` 不同。扩展命令在运行期间可能立即执行，不能统一当成排队聊天。完整队列管理界面仍留在后续阶段；停止行为遵循实际 Pi RPC，不能假设 abort 自动清空队列。

### 统计与扩展区域

输入区将上下文容量与累计 Token 用量分开。右下角的 `gpui_kit::component::progress::ProgressCircle` 只表示当前执行分支的上下文占用比例，不表示回答完成进度或费用。模型所在工具栏左侧紧凑显示输入、输出和缓存读取的累计数量；输入框下方独立状态行保留 Pi 扩展的余额等文本状态。这些数值均不是 Token/s 或网络速率。

- 两个入口各自只使用一个通用 Tooltip，以多行文本展示只读统计，不再使用 HoverCard 或点击弹窗。上下文圆环不带按钮式圆形悬停背景，外层只保留圆环本身的尺寸、可访问名称和提示触发区域。上下文卡片仅包含已用 Token、窗口容量、占比和自动压缩状态；用量卡片包含累计输入/输出、缓存读取/写入、最近缓存命中率和 Pi 统计费用。
- 统计呈现在 `features/home/composer/metrics.rs`。`get_session_stats` 提供累计 tokens、cost 和 contextUsage，`get_state` 提供 autoCompactionEnabled。CH 按 Pi footer 口径，由 entries 中最近 assistant 的 cacheRead / (input + cacheRead + cacheWrite) 计算；分母为零时不伪造数值。
- 累计用量包含所有分支及压缩记录；上下文比例对应当前执行分支，历史预览不会改变这一归属。费用注明为 Pi 统计值，不冒充账户实际扣费。
- 未建立会话时不显示伪造统计；上下文值未知（如刚完成压缩）时显示中性未知状态，详情说明暂不可用，不显示为 0% 或把未知状态当作持续加载。实际查询期间才使用加载反馈。
- 原生 RPC 未提供通用订阅模式标记，不凭模型名称生成 `(sub)`。

输入组件预留 `aboveEditor` / `belowEditor` 文本 widget 区域及扩展 status 区域，无内容时不占空间。该位置语义相对输入框，不是允许扩展任意插入或覆盖 Gupi 的统计圆环。扩展文本按来源会话与 key 更新、替换或清除，不因切换会话串到其他输入区；这些内容不属于用量统计，不统一藏进统计详情。

## 对话功能要求

主对话展示当前分支可追溯历史，压缩摘要有明确标记，压缩前原始内容折叠保留。选中会话后启动或复用 Pi，通过原生 RPC 获取正文和 entries；加载时显示进度，失败时显示实际错误，不另行解析离线正文。Pi 当前发送给模型的上下文与用户可浏览历史有不同用途，不以 `get_messages` 的结果替代全部历史。

文本提交后区分已接受、正在执行和已结束；工具过程显示名称、状态和必要摘要。错误后保留可恢复的输入与已有回答，停止等待 Pi 实际收尾后再允许依赖空闲状态的动作。模型与 thinking 选项来自 Pi 能力，并在选择后反映实际结果。

### 消息组件与过程折叠

复用 gpui-component 0.6.0 的 Message/MessageContent/MessageFooter、Bubble、Marker、TextView 和 MessageScroller，折叠容器使用现有 Collapsible。Message 提供行与内容布局，TextView 承接 Markdown、选择和代码块操作，MessageScroller 承接虚拟列表、流式尾随、锚点保持与返回底部；Gupi 只负责 Pi 内容映射和本轮过程/最终回答的分组策略，不复制这些通用实现。

- 用户消息通过 MessageAlignment::End 靠右排列，轻背景气泡沿用 Bubble 的最大宽度；正文仍左对齐。
- 过程采用三层折叠：整轮过程 → 文字之间的活动组 → 单个工具详情。运行时默认只展开第一层，模型文字用 Message 直接排版；连续工具调用及思考内容保持在同一组，只有模型的正文输出切断工具组。工具组与单项详情默认收起，不因新调用或执行更新自动展开。
- 整轮过程入口使用 Marker 的 Border 样式：标签和箭头靠左，底部绘制分隔线；结束后显示“已处理 + 耗时”，失败和停止使用对应状态。耗时从本段第一条助手消息的开始时间计算到末条消息的完成时间；完成时间来自 Pi entry 的记录时间，尚未刷新到历史的实时消息使用收到 message_end 的时间，缺少时间则省略耗时。活动组和工具项使用 Plain Marker，行高至少 24px，组内间距 4px。交互外层承接语义、键盘与折叠状态，不套居中的 Button 外观。读取、命令、查找、修改及其他工具分别使用书本、终端、搜索、文件编辑及扳手图标；单项右侧箭头只在悬停时出现。
- 展开的活动组最高 224px，超出后独立纵向滚动；ScrollHandle、ScrollableMask 和 Scrollbar 承接滚动与事件边界，边缘按实际偏移绘制最多 24px 的渐隐，抵达对应边缘后消失。渐隐使用当前背景色，不添加模糊滤镜。完整工具输出保留为代码文本，参数与输出位于同一个详情入口内。思考项也采用同级的单项折叠入口，默认只显示标题，点击后展开全文。
- 每个 toolCallId 只对应一个工具入口，执行更新和持久结果更新同一条记录，持久结果优先，空结果也能标记完成。历史定位会展开对应的整轮、工具组和工具详情。
- 正常完成：主阅读区保留最终回答，过程组自动收起为一个可展开的入口；用户可打开查看完整过程，不删除或截断历史数据。用户主动展开后，后续刷新不反复强制收起。
- Pi 没有 commentary/final 通道：只将末尾不带工具调用的助手文本作为回答候选，流式生成时直接显示；不会跨过后续工具消息将较早的进展当成最终回答。按用户决定在本轮正常完成后收起过程。
- 失败、中止或没有最终回答时不折叠整段过程，保留错误/中止反馈和已有文本。缺少调用记录的工具结果仍有独立入口；没有结果的已停止调用标为“未完成”。压缩前历史沿用折叠保留规则。
- 分组遵循 Pi 实际运行及消息关系；一次 tool/assistant message_end 不等于本轮运行完成，steer 和 follow-up 不能混入错误的运行组。
- 沿用 MessageScroller：在底部时跟随新增/流式内容，用户向上阅读后保持位置，通过返回底部恢复跟随；折叠或正文高度变化更新测量，避免重置整个列表导致跳动。

| setStatus / setWidget | 按前述 key 和位置更新或清除文本，不要求回执 |
| setTitle | 承接来源实例的标题提示，按窗口上下文显示；不把它当作 session 重命名，不写入会话文件 |

select/confirm/input/editor 统一采用临时输入区模式；Pi TUI 自身也会暂时替换普通输入区域，结束后恢复。保留普通聊天草稿与扩展编辑内容的边界，连续请求按实际 RPC 顺序承接。`setEditorText` 仍按设置普通输入文本的语义处理，不混同需回执的临时编辑请求。`setEditorComponent` 才是任意 TUI 编辑器组件替换，和 custom、setFooter/setHeader 一样没有原生 RPC 呈现能力。所有请求与状态更新关联来源运行实例和有效会话；需要回执时还绑定请求 id。后台请求保留来源，切换会话不误回复或覆盖别的会话草稿；切回来源会话时显示其待处理交互。

本机 `@juicesharp/rpiv-ask-user-question` 2.9.0 已核对源码：TUI 使用底部全宽 custom 浮层；RPC 检测 ctx.mode 后走标准 select/input。单选用 select，自由回答再请求 input，多选用 input 接收编号或自由文本，多题依次交互。Gupi 通过上述通用承接即可支持其 RPC 路径，无需复制插件问卷或解释选项文字来伪造多选控件。该 RPC 路径不包含 TUI 的标签页、并排预览和复核页。此处为源码核对，尚未运行 Gupi 插件交互验证。依据：[插件宿主说明](https://github.com/juicesharp/rpiv-mono/blob/main/packages/rpiv-ask-user-question/docs/hosts.md)。

## 会话历史列表

此节描述简略/详细列表的轨道布局；第三种[画布模式](history-canvas.md)使用相同详细投影，独立处理二维布局、连续段展开和视口。

分支树使用 Pi 的真实 entry 父子关系，彩色轨道按对话顺序从旧到新排列，最新记录位于底部。标题行提供互斥的图标 Toggle Group：默认简略模式只显示 user/assistant 消息；详细模式还显示工具结果、摘要及其他内容记录。两种模式均隐藏 label、custom、model_change、thinking_level_change、session_info 记录；没有正文的助手记录默认隐藏，当前助手节点及 stopReason 非 stop/toolUse 的异常记录保留。简略模式不因工具节点是当前 leaf 而显示它。标签从 label entries 读取并附在对应可见节点上，不强制显示被过滤的标签目标或分叉点。过滤只影响展示，不改变树关系；当前执行节点与正在预览的选中节点使用不同标记。

历史节点使用人物/蓝色表示用户、机器人/绿色表示助手回复；中间说明、思考、工具调用及工具结果使用不同图标和弱化颜色，失败/中断使用状态图标。轨道颜色只表示分支。普通节点去掉重复的角色副标题，标签使用行内标记。选中行只显示背景色，不绘制外圈边框；通过 List 的自定义条目接口保留键盘选择、虚拟滚动和菜单行为，不改全局主题。轨道上的当前节点双圆和预览节点方框保持独立。历史面板不提供过程展开按钮或隐藏数量徽章，也不加入手动分支折叠；节点仍按 entry ID 单独存在，预览不改变分支语义。

Pi 没有 final/commentary 字段：带 toolCall 的助手记录归为过程；普通助手正文若在同一父子链上、下一条用户消息之前仍接着助手或工具记录，也归为中间说明；其他分支的追加不会改变它的类型。无正文、思考、连接失败和中断有独立的本地化占位，不展示内部角色名。此处是展示分类，不增加新的 Pi 角色或导航命令。分类和 Markdown 纯文本摘要在 history.replace 时重建缓存，普通视图刷新不重复解析全文；原文和节点关系保持不变。工具结果按 toolCallId 关联调用记录，显示工具名称及路径/命令摘要；被过滤的调用记录仍参与摘要关联。时间使用本机时区的日期与时分秒。

右侧只保留分支树，以“会话历史”为标题；标题同行放置简略/详细图标切换和关闭按钮，图标的 Tooltip 同时提供可访问名称。模式为窗口内视图状态，切换会话和关闭面板后保持，不写入 Pi 会话。选中节点被过滤时选中最近可见祖先，不改变正文预览、草稿或执行 leaf。打开历史面板时滚到最新可见记录，切换模式时使选中节点可见；列表上下各保留 12px 内边距，节点仍为连续的 32px 行。节点时间通过通用 Tooltip 展示。

| 用户动作 | 展示变化 | 是否改变 Pi 会话 |
| --- | --- | --- |
| 点击树节点 | 预览节点/所在分支并定位正文 | 否 |
| 返回当前分支 | 回到实际执行 leaf 的对话 | 否 |
| 从这里另开会话 | 新会话进入目录并选中，保留来源链接 | 是，通过 Pi fork 创建独立文件 |

预览其他分支时显示固定的预览提示条及“返回当前分支”按钮；普通输入区保留草稿并暂停发送，返回后恢复。仅在当前执行分支内定位旧消息不进入其他分支预览，也不暂停普通发送。来源会话的扩展交互仍按既定临时输入区规则承接，其回执绑定实际请求，不受普通聊天发送禁用影响。

fork 的交互按 Pi 支持的用户消息位置提供，正文及历史中的该消息操作菜单使用“从这里另开会话”；点击任意工具或系统节点不会假装该节点可以直接 fork。复制当前完整路径对应 clone，与从历史用户消息分叉的含义不同，可按界面需要单独提供，不占用同一个含糊动作。

本阶段只使用 Pi 原生 RPC，不提供同一会话内的节点续聊、导航总结或导航标签写入。查看已有标签与分支关系不受影响；原生 fork 返回的文本用于新会话输入，不需要自带扩展或私有回执。

### 分支树实现方案

在 Gupi 内实现专用历史图，复用 `gpui_kit::component::list` 的虚拟滚动、选择、确认和菜单。参考 Zed Git 历史的轨道复用、固定图形列、曲线连接和裁剪方式。Pi 每条 entry 只有一个 parentId，使用单父节点轨道算法；不增加 Git 数据、协议或通用图形 crate。

| 层次 | 当前设计 |
| --- | --- |
| 顺序与投影 | Pi 按父节点先于子节点的顺序追加 entries；图沿用追加顺序，最新在下，不用可能相同或回退的 timestamp 推导拓扑。过滤后连接最近可见祖先，间接连接绘制虚线。 |
| 轨道分配 | 内部从叶节点向父节点反向分配轨道，完成的轨道供其他分支复用；显示坐标保持父节点在上、子节点在下，在父节点行绘制分叉曲线。每条轨道的边按显示顺序索引。轨道颜色取当前主题的分类色，颜色会循环，父子关系以实际连线为准。 |
| 绘制 | 全表固定 32px 行高，普通节点使用单行摘要。图形列独立，摘要左边缘统一对齐；节点直接画在线上，转角用二次曲线。每行使用相同行内坐标并裁剪到实际行边界，虚拟列表顶部或底部只有半行时仍衔接。当前执行节点为双圆，预览节点加方框；角色、时间与执行/预览状态在 Tooltip 中说明。 |
| 大量分支与宽度 | 图形列最多展示 5 条轨道、宽度最多 100px，保护窄面板中的摘要。超出时显示轨道范围、左右翻页和“定位选中”；支持在图形列横向滚动及 Shift+滚轮。各行共用同一个轨道偏移，选择节点自动显示其轨道。没有隐藏或合并原始分支，结束的轨道会复用。 |
| 数据与渲染开销 | 每条边只存一次，按来源轨道索引连续区间；二分查询当前行与可见轨道相交的线段，额外纳入从屏幕外接入当前节点的曲线。不为一条跨越上千行的边生成上千份片段。 |
| 交互 | List 负责上下键选择及点击/Enter 预览。当前执行 leaf、预览节点和选择项按稳定 entry ID 区分，查看图与横向浏览均不改变 Pi 执行节点。 |

实现位于 `state/history.rs`（可见记录）、`state/history/graph.rs`（轨道和边索引）、`features/home/history.rs`（列表和横向浏览）及其 `graph.rs`（曲线、节点和裁剪）。

## 浏览、运行与恢复

应用分别维护目录项、正在运行的实例、正文当前浏览位置和 Pi 执行 leaf。树节点选择、滚动、面板展开与输入草稿属于视图状态，不能触发隐式分支变更。

打开会话统一由 Pi 加载，再通过 RPC 获取历史。旧版会话由 Pi 恢复时迁移，Gupi 不重建迁移逻辑，也不把启动 Pi 宣称为纯只读操作。新建会话须确定 cwd，可沿用当前项目，没有当前项目时选择目录；Pi 尚未落盘的新会话由运行状态补入目录。应用内同一个会话文件只绑定一个写入连接，多个视图复用它；不同会话可以由独立 Pi 实例运行。关闭或隐藏一个面板不等于结束运行。

运行中允许浏览其他会话和分支，原会话继续执行并更新目录状态。fork 等会话操作在来源会话空闲时提供；不为了查看历史自动 abort。fork 会把同一个 Pi 进程切换到新会话，运行实例标识不会因此自动变化；事件与扩展回复须结合会话身份和绑定代次处理，不能仅按当前选中项或 InstanceId 路由。原会话保留目录项，再次继续时重新绑定或创建连接。

跨重启仅保存各会话非空的未发送文本草稿，不保存当前选择或滚动位置。重启进入新的空白页面，用户主动打开历史会话时才由 Pi 加载内容，执行分支遵循实际恢复结果；Gupi 不重放节点导航。fork 返回文本放到新会话输入，原会话草稿保留。草稿与 Pi transcript 分开存储，不把未发送文本写入 JSONL。读取草稿文件完成前暂停写回；退出等待已开始的读取合并，读取失败不覆盖原文件。旧空白页不再恢复为目录项，有内容的旧草稿保留。

## 交互约束

目录范围、读取方式和持久化范围已确定，下表汇总实施时遵循的交互约束。

| 场景 | 已定约束 |
| --- | --- |
| 新建或刚 fork 的会话如何出现在倒序列表 | 按既定目录规则选中并使其可见，不改写 Pi 活动时间；尚未落盘时仍保留目录入口 |
| 预览旧分支时如何继续 | 预览中提供“返回当前分支”及支持位置上的“另开会话”；没有同文件“从这里继续”。发送应明确归属当前执行分支，不能在旧分支预览下静默提交 |
| fork 文本与草稿 | 返回文本放入新会话，原会话草稿保留，未发送草稿跨重启保存。首版为文本输入，不自行补齐 Pi 未返回的附件 |
| 项目 cwd 已不存在 | 显示目录项与 Pi 实际恢复错误，不提供离线正文模式，不自行迁移或改写项目路径 |
| 运行中的会话有扩展交互，但用户正在看另一会话 | 仅通过侧边栏等待输入状态提醒，不额外弹通知或自动切换；用户点击来源会话后在其输入区域处理，回复绑定原请求和原会话，超时/取消后清理待答状态 |
| 会话恢复或 fork 结果不确定 | 按原生 RPC 结果与当前状态展示取消、错误或需要重新连接，不伪造已切换成功 |
