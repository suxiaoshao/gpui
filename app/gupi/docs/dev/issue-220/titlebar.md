# Gupi 统一标题栏设计

状态：Done。统一顶部、侧栏品牌行、会话菜单与当前 session 刷新已实现，完成受影响构建、关键回归和必要原生试用。

## 目标与范围

依据用户提供的 Gupi 与 Codex 截图，将窗口标题栏和会话工具栏整合，减少重复横栏，使侧栏、会话和历史面板具有连贯的窗口布局。保留原生窗口按钮及平台操作语义。

侧栏顶部使用 Gupi 品牌行与搜索按钮，下一行保留新建会话；项目列表及底部设置、刷新目录入口继续沿用。不引入新的 Pi 能力或会话数据结构。

## 当前实现与参考证据

- 改造前 `features/startup.rs` 在所有页面上方绘制 Gupi 和设置/返回按钮，`features/home.rs` 又在主内容列中绘制会话标题及面板开关。两层自绘顶部现已合并，主页面的顶部归 HomeView，其他页面复用相同的应用顶部基础层。
- 实际依赖 `gpui-component 0.6.0/src/title_bar.rs` 默认高度为 34px，macOS 默认左留白为 80px，默认背景有渐变。`TitleBar` 实现 `Styled` 和 `ParentElement`，可覆盖高度、背景、边框、左留白并组合应用内容，同时保留拖动、双击和平台窗口控制。
- `app.rs` 已使用透明标题栏和 `TitleBar::window_options()`。其中 `app_owns_titlebar_drag = true` 避免 AppKit 与应用重复处理标题栏拖动和双击。
- `HomeView` 的 `PaneLayout` 已负责实际左右面板宽度、最小正文宽度和窄窗口历史覆盖层。标题栏应读取同一份实际宽度，不另建侧栏宽度状态。
- 2026-09-11 只读检查本机 ChatGPT/Codex Electron `26.903.71938` 的 `app.asar`，`.vite/build/main-Bkkz0ENj.js` 的 primary 窗口在 macOS 使用 `titleBarStyle: hiddenInset`，原生按钮位置为 `x = 16`、`y = round((46 × zoom - 14) / 2)`。这里的 46px 是该版本原生按钮定位采用的顶部布局基准；不将截图像素直接当作 GPUI 逻辑像素。
- 实际 `gpui-pre 0.3.3` 提供 `TitlebarOptions::traffic_light_position`、`Window::set_traffic_light_position`、`start_window_move`、`titlebar_double_click` 和 `set_window_title`。macOS 后端保留系统按钮，重布局时更新位置，进入全屏时恢复系统按钮布局；双击读取系统偏好。无需先向 `window-ext` 添加 Objective-C 接口。

## 当前窗口布局

使用一条 46px 的顶部栏，分为与侧栏同宽的左区和占用其余宽度的会话区，不增加高度设置。

```text
┌ 原生红黄绿  侧栏开关 ───┬ 会话图标  会话标题  更多 ── 刷新 ─ 历史开关 ┐
│ Gupi              搜索  │                                           │
│ 新建会话                │                对话正文                   │
│ 项目与会话              │                             [历史面板]    │
│                        │                                           │
│ 设置 / 刷新目录         │                输入区                     │
└────────────────────────┴───────────────────────────────────────────┘
```

布局规则：

1. 顶部不再重复显示 Gupi 和另一行完整会话工具栏。应用名称由侧栏品牌行、系统菜单、窗口元数据及启动页面表达。
2. 左区背景使用侧栏主题色，分界线与下方侧栏边界对齐；会话区背景使用主内容主题色，去掉当前默认渐变。只保留必要的细分隔线。
3. macOS 红黄绿保持原生，在 46px 栏内居中；按当前 GPUI 后端按钮几何，以 `(16, 16)` 为初始位置，运行时核对系统实际按钮尺寸。侧栏开关位于原生按钮留白之后，整个左区随 `PaneLayout.left` 变化。
4. 会话标题左对齐、单行省略，完整标题由悬停提示提供；标题区可收缩，左右功能按钮保持尺寸。正文的 820px 阅读宽度不约束标题栏，标题栏按面板布局对齐。
5. 刷新当前会话和历史开关固定在会话区右侧。右侧历史面板的模式切换、搜索等局部操作仍归面板自身；打开面板不另加一条窗口标题栏。
6. 侧栏收起后，左区按内容收缩，依次为原生按钮、侧栏开关、新建会话图标和 20px 高的短竖线，再接会话标题。新建入口使用 SquarePen，与侧栏新建共用创建草稿及聚焦输入框的流程；侧栏展开时保留侧栏内的整行新建入口。窄窗口优先省略标题，不把按钮挤到原生按钮或窗口控制区。
7. 右侧历史覆盖层从标题栏下方开始，不能挡住顶部开关。普通宽窗口的历史列也从该位置开始，标题栏横跨主内容和历史区域。
8. 设置、引导、恢复和退出页面复用同一个顶部高度与窗口行为。设置页使用明确的返回入口及页面标题；引导/恢复页使用相应标题，不出现无效会话操作。现有页面切换不销毁保留的 HomeView。
9. 原生按钮保留系统失焦反馈，应用内容使用当前主题；全屏按系统按钮可见性调整左留白。标题栏不进入正文滚动容器。

### 侧栏开合

侧栏始终挂载，使用 `SidebarCollapsible::Offcanvas` 和明确的像素展开宽度，复用组件的 200ms 缓入缓出、滑出及延迟隐藏行为；不通过移除整个 Sidebar 实现关闭。隐藏期间保留最后展开宽度供动画使用，布局空间按隐藏状态释放，不改变保存的宽度偏好。标题栏左区使用相同时间和曲线的 `EffectTransition` 在展开宽度与窗口按钮区所需宽度之间过渡。

开关沿用组件库的 `PanelLeftOpen` / `PanelLeftClose` 两种图标，同时提供“展开会话侧栏”与“收起会话侧栏”的提示和可访问名称。应用保留自己的有标签按钮外壳及标题栏事件处理，不额外打包这两个组件图标。

按用户允许的取舍，暂不提供延迟悬停展开整条侧栏，普通按钮提示保留。当前 Sheet 的 `Root::open_sheet_at` 会主动转移焦点并清除正文选择，`close_sheet` 直接移除，只有进入动画；`overlay(false)` 不会取消这些焦点行为。它不能直接满足此处不打断正文操作、带退出动画的悬停预览，因此本轮不引入新的预览状态机或覆盖层。

## 已确定的入口

| 入口 | 当前安排 | 行为 |
| --- | --- | --- |
| 侧栏顶部 | 品牌行右侧提供搜索，下一行提供新建 | 搜索仍打开现有 Command 弹层 |
| 主页面右上角的重复设置入口 | 移除，保留侧栏底部与原生菜单/快捷键 | 侧栏收起时可重新展开，或用原生菜单 / Cmd+, 进入设置 |
| 会话标题后的更多菜单 | 复用已有会话右键菜单，提供重命名、定位、复制路径和现有连接操作 | 空白且没有运行实例时不显示；禁用条件与右键入口一致 |
| 刷新当前会话 | 会话区右侧，历史开关之前 | 重读当前会话状态和 entries，成功后更新统计等关联数据；不刷新整个目录 |
| Codex 的前进/后退按钮 | 本轮不增加 | Gupi 当前没有等价的页面导航历史；会话树的父子节点导航不能冒充浏览历史 |

分享、终端、审阅和分支选择等 Codex 功能不属于本标题栏方案。

刷新沿用 `connect` / `refresh`，已有连接不会重启；断开时按原有文件身份检查重新连接。没有会话文件、核心读取正在进行、会话命令或模型变更正在进行时禁用按钮。已有正文在刷新和失败时保持可见，失败显示实际错误，可再次刷新或使用现有重试入口；过期快照不覆盖更新的实时事件。Pi 的事件消费即使先收到事件流结束，也继续等待最终连接状态，确保会话收到断线通知后能够重连。

## 实现路径与职责

优先由 Gupi 自定义内容布局，底层复用现有 `TitleBar`。这允许改变视觉结构，同时沿用库对原生按钮、Windows 控制区域和 Linux 装饰模式的处理。若实现中发现现有组件的私有结构无法满足布局，再针对具体限制讨论共享组件改动，不先复制整份平台实现。

- `features/chrome.rs`：应用私有的顶部呈现辅助层，统一高度、主题、平台留白和内容槽位；不拥有会话、面板或路由状态。
- `features/home.rs`：先计算 `PaneLayout`，随后绘制顶部和下方列；正文列不再绘制重复 toolbar。`features/home/titlebar.rs` 提供会话标题、面板开关、刷新和菜单；标题沿用当前会话派生逻辑，不另存副本。
- `features/startup.rs`：主页面由 HomeView 绘制统一顶部；其他页面组合相同顶部基础层及对应返回/恢复内容。确保每条启动路径恰有一条标题栏，Root 的对话框和通知层继续在外层。
- `features/home/navigation.rs`：侧栏品牌行与搜索入口；顶部更多入口复用 `session_menu` 和禁用规则，不复制重命名或连接操作。
- `features/home/panes.rs`：继续作为面板实际宽度的唯一来源。调整历史覆盖层挂载位置，使其只覆盖顶部以下的内容。
- `app.rs`：保留 `TitleBar::window_options()` 的拖动配置，明确指定与新高度匹配的原生按钮位置；保留现有关闭、隐藏和退出生命周期。渲染对应页面时同步原生窗口标题，保持系统窗口列表与可访问名称一致。
- `locales`：只增加已确认入口缺少的语义文本；图标沿用现有资源，避免按参考图声明无实际入口的图标。

不需要新的依赖、Pi RPC、持久化字段或全局 UI 状态。无需改变其他应用标题栏。
