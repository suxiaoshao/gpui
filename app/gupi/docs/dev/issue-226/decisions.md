## 技术核验结果

- 统一面板按本地 action / Pi invocation 稳定身份保持选择，并在确认前重查 key、binding 和可用性；过滤或异步刷新不会将旧行号当作另一个命令。
- Pi 关闭返回的 CloseReport.status 表示是否观察到进程退出。重连沿用已有删除流程的退出确认边界；不重新设计 RPC 取消或推测 RAII 泄漏。
- Pi session-manager 的 _persist 在尚未首次写出且没有 assistant 消息时仅保留内存记录；sessionFile 非空不代表文件存在。空会话重连需对照应用字段区分此情况与历史文件丢失，不能把真正丢失的历史静默变成新会话。
- 重连保留当前模型/思考值是已确认行为。实现时核对启动参数及会话恢复的优先级，让恢复先于扩展启动钩子观察状态；不能在钩子完成后无条件 set_* 覆盖扩展的合法修改。原模型不能重新解析时反馈具体失败，不静默切默认值；不为此伪造 Pi 模型定义或 reload 生命周期。
- Pi 同 invocation 候选按 RPC 顺序保留首个展示项，真正执行由 Pi 分发；Gupi 本地动作不与 Pi 候选互相去重。统一面板查询原业务 context 的键位，不能因搜索框获得焦点丢失会话作用域。
- 应用退出与重连的启动阶段复用现有 draining/Task 所有权，确保退出时不重新拉起 Pi。必要时补具体交错回归，不扩大为新进程管理器。
