## 目标与入口

应用操作、当前会话操作与 Pi 资源命令使用同一个命令面板，共用候选模型、搜索、单行渲染、选择和键位提示。命令输入框同时支持逐字输入和 Tab 补全，两种输入方式使用相同编辑行为；不增加选中后必经的中间模式、命令标签或参数表单。发送复用会话现有流程。

| 入口 | 行为 |
| --- | --- |
| Cmd/Ctrl+Shift+P | 打开独立命令输入框，初始为空 |
| 普通输入开头新输入 / | 打开同一面板，以触发时的文字初始化；之后两个输入框互不影响 |
| Cmd/Ctrl+P | 会话快速打开，见 quick-open.md |

两个命令入口按当前可见页面显示适用命令，不提供额外范围切换。分类使用分组、图标和单行摘要。再次按命令面板快捷键只聚焦已有面板。

面板采用紧凑的输入区、列表、底部工具栏结构：Dialog 提供弹层、外框和默认遮罩，取消标题、顶部关闭按钮及默认内容留白。输入区和底部各用细分隔线；底部操作按钮靠右排列，以文字和实际绑定的键帽提示退出、补全、执行或发送，左侧不重复显示快捷键说明。加载、空结果或错误只在发生时显示，不常驻会话名称。Esc 与点击外部通过组件默认行为关闭面板。

命令输入区和主对话输入区沿用 Textarea 自带的内边距，外层不重复增加输入区的 padding；工具栏单独保留所需间距。

## 页面上下文与连接状态

先根据当前可见页面确定会话目标，再根据该会话的连接和业务状态投影候选。后台是否存在 Pi 进程不决定当前页面显示哪些命令。

| 页面 / 状态 | 显示规则 |
| --- | --- |
| 设置页、启动页，没有可见会话 | 仅该页面适用的应用命令，不借用隐藏 HomeView 的 selected session |
| 对话页，当前会话就绪 | 应用命令＋当前会话操作＋该会话 get_commands 的资源命令 |
| 新对话正在建立或复用连接 | 应用与可用的本地会话操作照常显示，Pi 分组显示加载状态 |
| 当前会话未连接、断线或正在重连 | 本地操作按各自条件保留；Pi 分组显示连接状态，旧 binding 的候选不可用 |
| 同一连接的 get_commands 正在读取、失败或返回空表 | 分别显示加载、错误/重试或无资源命令；沿用同 binding 的缓存与重试，不把读取失败伪装为空表 |
| 其他会话在后台运行 | 不合并后台会话的命令；候选始终绑定当前可见会话 |

对话页内输入框、消息区、侧栏、历史区持有焦点时都可打开统一面板。目标是当前打开的会话，不是侧栏悬停行或历史预览节点。离开对话页后无会话目标；不要求输入框一直持有焦点。

没有目标时隐藏会话组；有目标但某项暂不可用时禁用并说明原因。运行中、提交中、历史预览和扩展待答等条件复用现有业务门禁，不因统一面板增加“停止中禁止发送”等新规则。RPC 没有每条插件命令的忙碌可用性声明，不猜测该元数据。

面板自身不为发现命令启动 Pi。新对话的真实初始化继续由会话页面负责；闲置且未发起连接的空草稿不能仅因打开面板显示持续 loading。执行已有重连等动作时沿用其业务行为。

## 分类与单行布局

默认依次分组为「应用」「当前会话」「插件命令」「技能」「提示词模板」。空组隐藏；连接/读取状态行保留用于说明 Pi 候选为何不可用。

- 每行按「图标、名称、灰色简短说明、右侧辅助信息」排列。名称优先，说明空间不足时省略；tooltip 展示完整说明与 RPC 提供的来源路径。
- 本地动作使用对应操作图标；插件用拼图、技能用书本、模板用文档，采用项目现有 Lucide 资源与主题。不仅靠颜色区分类型。
- 本地动作右侧显示实际快捷键；Pi 资源右侧显示 sourceInfo.scope 对应的「个人 / 项目 / 临时」。来源缺失时不猜测，包名与路径放详情。
- 搜索匹配名称、说明和显式搜索别名，支持中文名称及 model、/model 等原始命令名；分组下保持可辨认的结果。使用受限高度滚动，键盘选择项始终进入可见区域。
- 技能可显示易读名称，但执行仍保留完整 invocation，例如 /skill:名称。图标、类型和来源标签不能改变 Pi 的实际分发。
- loading/error/empty 不作为可执行候选。底部右侧显示「退出 Esc」「执行 Enter」按钮，选中 Pi 候选时增加「补全 Tab」。无候选且当前允许原文提交时，执行按钮改为「发送 Enter」；没有 Pi 候选时不显示补全按钮。描述使用组件的 `truncate()` 保持单行并在溢出时显示省略号。

```text
当前会话 · UI 调研
[模型] 选择模型与思考等级   修改当前会话的模型          ⌘⌥/
[历史] 会话历史             查看历史，或选择用户消息分叉
插件命令
[拼图] /draft-show          查看当前草稿                个人
技能
[书本] 写作                根据既定风格组织正文        项目
提示词模板
[文档] /review             检查当前改动                临时
```

按钮、图标、侧栏与面板的快捷键统一从实际 action/context 查询，详见 [actions.md](actions.md)。Pi get_commands 不提供插件键位，不虚构快捷键。

## 候选身份与执行

统一发现与选择，不将所有候选转换为 /xxx prompt。

| 候选 | Enter | Tab | 点击 |
| --- | --- | --- | --- |
| Gupi 本地动作 | 执行当前选中 action，或打开已有选择器；沿用业务门禁 | 保持组件焦点语义，不执行，不伪造 / 别名 | 执行/打开 |
| Pi 插件、技能、模板 | 将当前选中项的完整 invocation 与已有命令参数提交一次 | 将当前选中项的命令补全到输入框，不发送，继续编辑 | 按补全处理，继续编辑 |
| 无候选 / 候选已收起 | 提交输入框的完整文本，交由 Pi 处理 | 没有可补全项时不修改文本、不提交 | 无候选可点击 |

候选列表打开时，输入文字过滤候选，上下键改变选中项；Enter 执行当前选中项。仅移动选中项不会执行或改写输入。无候选时直接提交当前完整文本，不要求先按 Esc，也不根据是否以 / 开头将文本判成可发送或不可发送的类别。文本提交后由 Pi 决定执行扩展、展开模板/技能、交给输入钩子或作为普通消息处理。

所有提交仍需有当前可见会话目标，并满足已有提交条件；空白输入不提交，设置页不借用隐藏会话。选中项因禁用或目标/binding 失效而不能执行时，沿用该项的校验结果，不将它当作无候选后继续发送原文。

例如输入 /rev、当前选中 /review：Enter 提交 /review；Tab 补成 /review 并在末尾需要时补空格，用户可继续输入参数。手动逐字输入到 /review 后继续写参数，与 Tab 补全后的编辑行为相同。已有参数、空格和换行不能被补全覆盖；光标进入参数后不继续把参数当作命令名称筛选。

Pi RPC 没有参数 schema，客户端不猜测必填参数或生成表单。这不妨碍用户按 Enter 明确执行；需要参数时可先 Tab 补全或手动输入，再按 Enter 提交。

本地候选使用 action 身份，Pi 候选使用所属 session、binding 和真实 invocation。两者同名仍保留类型区别，不互相去重；Pi 内部同 invocation 沿用 RPC 顺序保留首个展示项，实际分发由 Pi 决定。直接输入 /文字仍交给 Pi；本轮不新增将任意 /文字解释为 Gupi action 的别名层。

### 原始命令名搜索

原始名称只参与候选搜索，不作为正文命令解析器；输入 model、/model 或 thinking 均能找到现有模型与思考选择器。只有明确执行本地候选才路由到对应 action，不向 Pi 发送 prompt，也不解析原始命令参数。Pi 同名候选保留自己的类型、补全与提交行为。

| 搜索别名（均支持带 /） | 本地候选与行为 |
| --- | --- |
| settings | 打开 Gupi 设置，当前不包含全部 Pi 设置 |
| model、thinking | 同一个“选择模型与思考等级”候选，打开已有 Picker |
| tree、fork | 同一个“会话历史”候选，打开已有面板；已打开时保持展开，由用户明确选择消息 fork |
| export | 导出会话，打开现有 HTML 保存窗口 |
| compact | 压缩上下文，调用 Pi compact RPC |
| copy | 复制实际执行分支的最后回答，不使用历史预览或悬停消息作为来源 |
| name | 打开现有改名窗口 |
| clone | 执行现有会话复制 |
| new | 执行现有新建 |
| resume | 打开会话快速选择 |
| reload | 执行现有当前 Pi 重连 |
| quit | 退出 Gupi |

14 个原始命令名映射到 12 个本地候选。模型/思考和历史/fork 不重复列项；复制路径等不同操作仍独立保留。应用与会话操作使用同一份 action 门禁，原有导出按钮也路由到同一个 Export action。历史工具栏及快捷键仍负责展开/收起，面板中的“会话历史”只负责打开，不因重复执行关闭面板。无默认快捷键的新增动作不虚构键位。

session、hotkeys 仍缺完整界面；scoped-models、import、share、changelog、trust、login、logout 没有对应管理 UI。本次不把它们加入可执行候选。JSONL 导出仍未接入。

## 输入与提交

命令面板使用独立输入框，文字只用于本次打开的过滤、补全和发送。输入、执行和关闭都不回写正文，不按会话保存或恢复面板文字。正文中的单独 / 可以在退出后继续作为普通输入编辑和发送。

- 有候选时，Enter 执行选中项；Tab 或点击 Pi 候选只补全命令名，保留已有参数、中文和换行。本地动作调用原有入口。
- 没有候选时，Enter 将非空完整文本交给当前 Pi；不区分搜索词与命令文本，不根据旧选择阻止提交。
- Tab 后仍在同一命令输入框编辑；进入参数区隐藏候选，回改命令名可以重新显示。收起候选不会关闭输入框。
- Esc 关闭面板并返回正文；不把面板文字复制回去。/ 入口退出后，继续编辑原正文不会自动重开；删除开头 / 再输入，或显式使用快捷键，可以重新打开。
- 发送时先不清空输入，按钮 loading 且禁止重复发送，输入暂时只读。Pi 确认成功后结束本次面板输入；失败时不清空并通知。这里没有另存失败文本、恢复按钮或关闭后恢复的功能。
- 普通消息输入继续使用同样的“确认成功后才清空”流程；它原有的正文草稿保存不扩展到命令面板。

## 焦点与目标

打开时捕获当前可见会话及原焦点，确认前校验目标和业务条件。切换页面、会话或连接绑定失效时关闭面板，不把旧命令交给新目标，也不引入必须重选的中间状态。扩展交互到达时让出面板，沿用原有交互入口。

本地 action 在关闭面板并恢复焦点后派发。Enter/Tab/Esc 只处理一次；中文 IME 组词优先。普通输入在退出面板后发送 /xxx，仍由 Pi 决定是否解释为命令。

## 实现归属与依据

- HomeView 提供可见会话上下文，ConversationState 提供现有命令读取和提交流程；面板自己持有临时输入。PiState 继续管理实例。
- 复用 Command/CommandState 的列表、方向键、选中项和滚动，不维护镜像选择或逐帧回写选中项。
- Command 当前内置搜索框为单行，隐藏它也会关闭本地过滤。为保留多行参数和光标回改命令名，使用通用 Textarea 作为 Command 的 header；只适配命令名过滤、Tab 和原文提交。不改共享组件契约。
- send_text 接受本次完整文本，复用会话提交任务、门禁和错误通知，返回接受结果。命令文字不进入 Session 或持久化文件；正文发送成功仅清理仍属于该次提交的正文。
- 不建立第二份 Pi 命令缓存、RPC、数据库或后台服务。快速打开继续使用自己的目录数据。
- 本地 Zed crates/command_palette/src/command_palette.rs 的 new 从 available_actions 收集并过滤动作，confirm 恢复 previous_focus_handle 后派发，render_match 按原焦点查询键位。crates/gpui/src/window.rs 的 available_actions 按焦点路径及全局 listener 枚举。借鉴上下文保存和派发，不据此宣称 Zed 已合并其 agent slash UI。
- Pi rpc-mode.ts 的 get_commands 提供 extension/prompt/skill 和 sourceInfo；不包含 TUI 内置表。完整内置能力判断以 builtin-commands.md 为准。
- 本地 Pi packages/tui/src/components/editor.ts 的 autocomplete 分支：Tab 调用 applyCompletion 后返回；Enter 对 / 前缀先补全选中项，再进入 submit。非 / 补全的 Enter 只补全，不能将本次命令规则推广成所有补全均立即发送。无候选时取消补全，再按正常输入提交；interactive-mode.ts 分发内置命令，未命中的文本继续进入正常会话输入。Gupi 无候选文本统一交 Pi，不自行补上 TUI 内置命令解析。

## 必要验证

检查两个输入框独立、关闭重开不恢复面板文字；方向键/鼠标选择、Tab 参数编辑和无候选 Enter；提交期间不清空与禁止重复，成功结束、失败原框不变；正文和其他会话不受命令提交影响。验证记录见 [validation.md](validation.md)。额外内置命令仍按 builtin-commands.md 单独确定。
