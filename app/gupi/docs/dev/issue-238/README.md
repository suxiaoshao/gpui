# 消息摘要与工具详情的查看和复制

归属 [#238](https://github.com/suxiaoshao/gpui/issues/238)，父 Issue #217。摘要及工具详情已迁移至 Dialog；复制粒度、详情组织、输出跟随和历史定位行为均按已确认方案实现，当前没有待确定问题。

## 目标与已确认范围

长摘要、文件内容、diff 和命令输出有独立的阅读空间，可以方便地选择、复制，不再把消息列表撑开。消息仍能直接说明执行了什么、运行到哪里。

| 对象 | 目标行为 |
| --- | --- |
| 压缩摘要 | 时间线保留紧凑的压缩记录入口；点击打开 Dialog，完整展示 Markdown，支持文字选择和“复制全部”。复制原始摘要文本，保留 Markdown 格式 |
| Read / Skill / Write | 在详情 Dialog 中展示路径、已有参数以及读取或写入的内容，支持内容复制 |
| Edit | 在 Dialog 中展示 Pi 返回的 diff；没有实际 diff 时保留现有请求内容的查看能力，不自行读取文件构造修改结果 |
| Bash / PowerShell | 在 Dialog 中查看命令、输出及状态，运行中的结果持续更新 |
| 自定义工具 | 在 Dialog 中查看参数、返回内容和附加详情，保留文字与图片等内容块顺序 |
| 消息中的过程 | 保留本轮过程和工具分组，以及工具名称、路径或命令摘要、运行状态和简短错误信息；去掉单个工具完整详情的内层展开 |

思考过程、普通回答和分支摘要保持现有展示；用量浮层、用户消息图片预览和输入框附件不在本轮改造范围。工具返回图片仍需正常展示，不借此次迁移增加图片复制、下载等功能。压缩记录的位置和前后回答的顺序保持，不将此前消息重新装进一个摘要容器。

关闭详情只是结束查看，不停止工具或 Pi。主窗口和临时窗口共用展示实现，不修改 Pi RPC、会话存储格式、通知体系或窗口失焦策略。

## 实现位置

使用现有 GPUI Kit 0.6.4 的 Dialog、TextView、Button 和滚动组件，无需升级依赖。

- [details.rs](../../../src/features/home/messages/details.rs)：窗口持有的 `DetailsView`，负责摘要与工具入口、详情弹窗、可选择文本、工具定向更新和滚动跟随。
- [tool_details.rs](../../../src/features/home/messages/tool_details.rs)：沿用工具分类、路径/参数、实际 patch 优先和混合结果投影，输出连续分区与各区可复制文本；图片和元数据不混入复制结果。
- [actions.rs](../../../src/features/home/messages/actions.rs)：消息与详情共用复制按钮、短暂反馈和复制失败处理。
- [messages.rs](../../../src/features/home/messages.rs)、[presentation.rs](../../../src/features/home/messages/presentation.rs)：摘要和单个工具改为详情入口；保留过程、分组、思考折叠。历史定位只展开必要过程和分组。
- [activity.rs](../../../src/features/home/messages/activity.rs)：仍由 `RunContent::project` 统一投影历史消息与实时工具活动；工具调用标识在实时转历史后保持稳定。
- [conversation.rs](../../../src/state/conversation.rs)：复用按来源 session 区分的 `ConversationEvent::Changed`；没有新增 RPC、全局刷新或结果存储。
- [temporary.rs](../../../src/features/temporary.rs)：沿用现有 Dialog 优先动作路由，Esc 关闭详情后仍保留临时窗口及会话。

稳定行为同步至[应用说明](../../../README.md)、[运行过程展示](../issue-229/runtime-display-plan.md)和[历史导航](../issue-220/history.md)。局部更新约束沿用[事件同步与局部刷新](../issue-236/README.md)。

## 实现设计

### 所有权与数据来源

实现位于 `features/home/messages/` 的私有 `details` 模块，共用详情视图和内容投影。

`ConversationState` / `Session` 继续拥有会话、历史和实时工具事实。窗口内的详情视图只拥有查看目标、文本渲染实体、选择、滚动和复制反馈等 UI 状态，不复制一整份会话、不建立第二套结果存储或应用级 Global。

摘要打开时读取该记录的原始文本；工具查看目标由来源 session、现有投影工具调用 ID 和当前历史预览上下文组成。实时消息 ID 转为历史条目 ID 后仍显示同一次工具调用，不依赖列表位置，不另造业务 ID。Dialog 打开期间无法通过父界面切换上下文；不为会话切换、历史分支切换或删除目标增加专门的兼容监听、自动关闭逻辑或测试。

历史详情只反映 Pi 已记录的内容。不得重新执行工具、重新读取当前磁盘文件替代历史结果，也不因为查看详情新增 RPC 或目录扫描。现有代码对 Pi 截断、完整输出路径和未知结果的处理继续保留，不宣称能显示 Pi 未返回的内容。

### 局部更新与文本渲染

详情视图按来源 session 过滤既有变更批次，在相关消息/工具实际变化时更新对应渲染状态；无关会话的流式事件不刷新详情正文。未打开详情时不维持详情专用观察任务，关闭或窗口销毁时释放 UI 订阅。

使用组件的 `TextView` / 代码高亮与滚动能力。详情按分区和内容块位置保留自己的 `TextViewState` 实体，只更新变化的文本。弹窗解析、选择和滚动不调用 `MessageScroller` 的行重测，也不借用消息行的 Markdown 状态。

现有工具更新是结果快照；不要把累积输出再次追加造成重复。只有文本为既有文本的真实前缀扩展时才走增量解析；替换、失败或结束状态沿现有数据更新。关闭弹窗不发 abort，也不影响其他视图。

### 展示与交互

时间线入口表达“查看详情”，不再使用表示原位展开的工具箭头。保留当前摘要与状态，键盘可打开；图标按钮具备可访问名称和简短 Tooltip。

弹窗标题区显示对象名称及必要状态，正文按工具类型组织，并使用单一主要纵向滚动区域。路径和命令等上下文靠近对应内容，避免在标题、正文和尾部重复。沿用主题、组件尺寸及窗口可用空间约束，不将现有带框详情卡片原样塞进另一层大框。

压缩摘要使用可选择 Markdown，标题区提供“复制全部”，复制原始摘要而非渲染后的文本或附加标题。工具内容复制粒度见 D-01。复制采用既有剪贴板能力与短暂按钮反馈，复用已有复制失败处理，不新增全局成功通知。

Esc 只关闭最上层详情，焦点返回原触发项；若触发项因列表虚拟化不再挂载，回到所属消息区域的合理焦点，不强迫消息列表跳至末尾。保留已有阅读锚点，不另存一套会话/滚动状态。临时窗口失焦时仍遵循当前窗口销毁和全局会话保留策略，不为详情改变窗口生命周期。

## 已确认交互决策

用户已确认以下四项；当前没有待确定问题。

| 编号 | 对象 | 决策 | 理由 |
| --- | --- | --- | --- |
| D-01 | 工具复制范围与按钮位置 | 按内容区复制：命令、输出、diff、参数/附加 JSON 各自在对应区标题旁提供复制按钮；文件类复制已展示的内容。不增加工具混合“复制全部” | 避免把路径、命令、输出拼成用户不需要的格式；JSON 复制当前格式化文本，不把图片 Base64 混入文本。摘要保留“复制全部” |
| D-02 | 详情组织 | 使用连续分区，不使用 Tabs，也不强制每种工具都有“输入/输出/详情”栏目。Read/Skill 以文件内容为主，Edit 以 diff 为主，Shell 的命令在输出上方，自定义工具按实际返回内容组织 | 少一次切换，方便联系参数与结果 |
| D-03 | 运行中输出跟随 | 已在底部才跟随；向上阅读或正在选择文字时暂停跟随，回到底部后恢复。复制读取点击时的当前完整内容，不冻结工具运行 | 兼顾观察最新日志和稳定阅读；复制不包含点击之后才产生的输出 |
| D-04 | 历史定位 | 只定位到对应消息入口，展开必要的过程/分组；用户再点击查看详情。移除定位逻辑中对已不存在的最内层展开状态的写入 | 保留“定位”的导航含义，避免浏览历史时连续弹窗 |

工具结果中的图片继续按现有内容展示。用户消息的图片预览保持不动；工具图片点击放大若有新增需求再讨论，不在迁移正文时顺带引入叠加弹窗。

## 验证结果与交付边界

- `cargo test -p gupi --quiet`：222 项通过。新增回归覆盖分区复制、混合结果顺序及排除图片 Base64、无关会话事件过滤、同次工具调用实时转历史的标识变化、保留文本实体、文字选择暂停跟随、关闭后释放详情视图，以及临时窗口 Esc 只关闭摘要 Dialog。历史定位回归已删除过时的摘要内层展开断言。
- `cargo clippy -p gupi --all-targets -- -D warnings`、`cargo build -p gupi --quiet` 通过。依赖 `block 0.1.6` 仍有已有的未来 Rust 不兼容提示。
- 原生主窗口使用隔离配置与录制 session，未请求真实模型：验证长摘要 Markdown 和代码高亮、长输出滚动、diff 高亮、关闭后返回原消息。摘要“复制全部”与原始 1082 字符 Markdown 完全一致；120 行工具输出逐字一致；diff 选中文字复制得到 `+new`。
- 同次工具更新、来源过滤、选择暂停跟随及订阅释放由组件/状态测试验证；临时窗口的 Dialog/Esc 路由由真实视图组件测试验证。本轮未额外进行原生运行中工具输出跟随或原生临时窗口验收，不将这些记作人工验证通过。
- 没有追加全 workspace、跨平台或打包验收。Dialog 打开期间上下文切换的兼容逻辑不在本次范围；全局系统快捷键入口也未改动。
