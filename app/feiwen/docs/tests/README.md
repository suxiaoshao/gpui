# feiwen 测试步骤文档

本文档与 `../features/` 一一对应。测试目标是验证用户可见行为，不验证 Rust 模块结构。每条测试必须写清具体输入、按钮、观察点和清理方式，方便人工执行，也方便 agent 使用 `computer-use` 执行。

## 数据隔离与预置规则

- 不使用用户真实数据库、真实 Cookie、真实抓取入口或真实导出目录作为测试对象。
- 每次手测必须使用已确认隔离的测试进程或操作系统 profile；仅创建一个临时目录并不会改变应用实际打开的数据库路径。
- 如果测试目标不是“抓取真实分页流程”，但需要小说、作者、标签或章节数据作为前置条件，优先通过测试 fixture 或临时 DuckDB 数据库准备数据。
- 抓取类测试优先使用本地 mock HTTP 服务或测试 fixture。只有专门的 live smoke 测试才允许访问真实站点，并且不能作为质量门禁。
- Cookie 使用测试占位值，不截图、不提交、不记录真实 Cookie。
- 测试结束后删除测试数据库、mock 服务数据、日志截图和临时配置。

## 预置数据建议

当前应用会固定打开操作系统配置目录下的 `top.sushao.feiwen/data.duckdb`，没有公开的数据库路径覆盖选项。只有在测试进程或操作系统 profile 已被确认隔离时，才执行手工数据库测试；否则应停止，不能改用默认用户数据库。

建议优先使用代码中的临时 DuckDB 测试辅助能力准备 fixture。若手工环境已经实现独立 profile，可在首次启动创建 schema 后关闭应用，通过 DuckDB 工具写入小说、标签和关联关系，再次启动并确认页面只显示 `QA` 前缀数据。

如果不能确认数据库路径，停止测试并先定位测试环境，不要继续操作默认用户数据目录。

## 用例格式要求

每个非 README 测试文档必须包含以下结构：

- `测试目标`
- `数据隔离`
- `测试前提`
- `测试数据`
- `测试步骤`
- `预期结果`
- `边缘情况`
- `清理`

步骤必须能直接执行。不要写“填写信息”或“执行查询”；要写“在 `入口链接` 输入框填写 `http://127.0.0.1:18081/books`，点击 `开始抓取` 按钮”。
